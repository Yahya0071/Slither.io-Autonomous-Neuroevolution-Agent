# Contributing to SlitherML

Thank you for your interest in contributing to SlitherML. This project is dedicated to algorithmic research in autonomous continuous control, neuroevolution, and imitation learning.

---

## Design Principles & Strict Rules

1. **Zero External Dependencies**:
   - The runtime and test suite use only Node.js built-in modules (`node:fs`, `node:crypto`, `node:test`, `node:assert/strict`, `node:path`, `node:url`).
   - Do **not** install npm packages or add `dependencies` / `devDependencies` to `package.json`.

2. **Modularity (`src/`) & Single Source of Truth**:
   - Hand-edited source code lives under `src/`:
     - `src/network.js`: Neural network, forward pass, SGD, mutations, crossover.
     - `src/flight-recorder.js`: Flight telemetry, death autopsy deduction, breadcrumbs.
     - `src/perception.js`: Proximity ray casting, food radar, corridor search, combat geometry.
     - `src/stances.js`: Tactical combat arbiter, steering assists, boost governor.
     - `src/evolution.js`: Rollout evaluation, consistency gating, mutation schedules.
     - `src/agent.js`: Core agent state machine and persistence hooks.
     - `src/controller.js`: Browser interface, HUD overlay, event handlers.
   - **Never manually edit distribution files**: `console_inject.js`, `extension/agent.js`, `slither_ml_agent.user.js`, and `quick_start.html` are strictly generated by `build.mjs`.

3. **Checkpoints Policy**:
   - Do not commit experimental or local training checkpoint dumps into git.
   - Only validated release checkpoints (e.g. `checkpoints/slither_ml_brain_gen100.json`) belong in version control.
   - Archive personal checkpoints outside git in `checkpoints_archive/`. See [docs/CHECKPOINTS.md](./docs/CHECKPOINTS.md).

4. **Deterministic Testing**:
   - All tests in `tests/` must be deterministic.
   - Seed all pseudorandom number generators (`mulberry32`).
   - Do not use arbitrary `setTimeout` delays in tests; use simulated or mock clocks.
   - The entire test suite must run in under 2 seconds.

## Development Workflow

### 1. Setup
Requires Node.js ≥ 22.8:
```bash
git clone https://github.com/Yahya0071/Slither.io-Autonomous-Neuroevolution-Agent.git
cd Slither.io-Autonomous-Neuroevolution-Agent
```

### 2. Making Changes
1. Create a feature branch:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. Edit files under `src/` or `tests/`.
3. If changing behavioral formulas, add a test in `tests/` reproducing and verifying the behavior.

### 3. Building & Testing
After making any change to `src/`, always run:
```bash
# Bundles src/ into console_inject.js and the other 3 distribution targets
npm run build

# Runs all unit and behavioural tests (must pass completely with 0 failures)
npm test
```

### 4. Code Style & Commit Conventions
- Keep code clean, readable, and well-commented.
- Preserve existing comments and docstrings.
- Avoid promotional superlatives or unsubstantiated claims in documentation.
- Use clear commit messages following conventional format (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `ci:`).

---

## Pull Request Checklist

Before opening a pull request, verify that:
- [ ] `npm run build` succeeds and reports all 4 artifacts match byte-for-byte.
- [ ] `npm test` passes all tests with zero failures or skips.
- [ ] No npm packages or external dependencies were introduced.
- [ ] No unauthorized training checkpoints were staged.
- [ ] New behavioral logic is covered by automated unit/regression tests.
